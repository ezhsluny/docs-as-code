# Model Card

## Общая информация

**Название модели:** `yashpwr/resume-ner-bert-v2`

**Источник:**  
[https://huggingface.co/yashpwr/resume-ner-bert-v2](https://huggingface.co/yashpwr/resume-ner-bert-v2)

**Автор / организация:**  
Пользователь Hugging Face `yashpwr`.  
Организация-разработчик явно не указана.

**Задача модели:**  
Named Entity Recognition (NER) для резюме и CV.  
Модель размечает текст резюме 25 типами сущностей: имя, email, телефон, локация, компании, должности, навыки, опыт в годах, степени, учебные заведения, годы выпуска и др.

**Язык:**  
Английский (`en`).  
Модель оптимизирована для англоязычных резюме; поддержка русского языка авторами не заявлена.

## Использование в проекте

В проекте Resume Analyzer модель используется на шаге **первичного извлечения структурированных данных** из загруженного резюме.  
После того как система получает текст резюме (например, после OCR / извлечения текста из PDF), он передаётся в NER-пайплайн на базе `yashpwr/resume-ner-bert-v2`.

Результат работы модели — набор сущностей и их BIO-тегов — далее агрегируется и преобразуется в структуру, соответствующую полям API `AnalysisResult`:

- `skills` — из сущностей типа `SKILL`;
- `education` — из `DEGREE`, `COLLEGE NAME`, `GRADUATION YEAR`;
- `experience` — из `COMPANIES WORKED AT`, `DESIGNATION`, `YEARS OF EXPERIENCE`.

Извлечённые данные сохраняются системой и в дальнейшем участвуют в сопоставлении резюме с вакансией и ранжировании кандидатов (`/vacancies/{vacancyId}/candidates`).  
Модель не принимает финального решения о найме; она выполняет только извлечение сущностей.

## Входные данные

- Текст резюме на английском языке.
- Предпочтительно — plain text после извлечения из PDF/DOCX.
- Максимальная длина последовательности — 128 токенов; более длинные тексты обрезаются или требуют разбиения на фрагменты.

## Выходные данные

- Список сущностей в формате BIO-тегов:
  - `B-<ENTITY>` — начало сущности;
  - `I-<ENTITY>` — продолжение сущности;
  - `O` — не сущность.
- Типы сущностей включают: `NAME`, `EMAIL`, `PHONE`, `LOCATION`, `COMPANIES WORKED AT`, `DESIGNATION`, `SKILLS`, `YEARS OF EXPERIENCE`, `DEGREE`, `COLLEGE NAME`, `GRADUATION YEAR` и др.

## Метрики качества

| Метрика | Значение |
|---|---|
| F1 Score | 90.87% |
| Precision | 91.44% |
| Recall | 90.81% |

Это агрегированные метрики на обучающем/валидационном наборе; методика расчёта и тестовый набор не детализированы.

## Ограничения

1. **Язык.** Модель оптимизирована только для английских резюме. Для русскоязычных резюме качество не гарантируется.
2. **Длина контекста.** Оптимальная работа — до 128 токенов; длинные резюме обрезаются, что может приводить к потере части сущностей.
3. **Формат и домен.** Модель лучше всего работает с текстовыми резюме из технологической и бизнес-сферы; сложные, нестандартные или сканированные документы без OCR могут снижать качество.
4. **Потенциальное ограничение для нашего проекта:** поскольку модель обучена на англоязычных данных, для русскоязычной части проекта потребуется либо отдельная модель, либо перевод, либо дообучение.

## Не рекомендуется использовать

- Для юридических или медицинских решений, где ошибка извлечения сущности может иметь правовые последствия.
- Для языков, отличных от английского, без предварительной проверки качества.
- Для извлечения общих именованных сущностей (модель специализирована на резюме).
- Как единственный источник решения при найме — результат должен проверяться человеком.
